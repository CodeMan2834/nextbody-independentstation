## 结论与交付状态

原后台不能直接作为可交付的线上内容维护系统：线上公开配置仍连接访问者本机的 `http://localhost:8081/api/v1`，登录只是浏览器端默认凭据校验，保存内容也不会自动更新线上。

本次已在主工程完成修复，**17 项自动化测试、19 项本地浏览器集成检查、生产构建及本地生产模式检查均通过**。网站核心内容已形成可配置、可保存、可回读的链路，并提供中文维护手册。

**当前结论是“本地修复与验证通过，线上开通及验收待完成”，尚不能宣布线上运维交付完成。** 本次没有将代码推送到 GitHub，也没有修改 Vercel 环境变量或部署正式网站。线上仍保持检查开始时的旧版本。

## 2. 内容覆盖与固定边界

| 内容 | 运维可维护范围 | 固定或需开发处理的部分 |
| --- | --- | --- |
| 全站 | 品牌名、页脚短句、联系邮箱、WhatsApp、导航、社交链接、页头按钮 | 视觉 Logo 形状、布局、字体、全局默认 SEO、权限与密钥 |
| 首页 | 首屏媒体、标题、标签与按钮，价值、流程、报告、F20 影片、系列/案例标题、行业、服务、FAQ、行动区 | 区域版式与顺序、首屏铺满/裁切策略、滚动效果；每条媒体独立文案尚不支持 |
| 产品 | 既有三款的图片、介绍、参数、报告、行业、场景、下载文件 | 新增产品种类、产品地址、旗舰分类、通用区块小标题与按钮微文案 |
| 案例 | 增删、排序、图片、场景、标题、结果 | 卡片布局；没有独立案例详情页。需求/解决方式等字段明确标为内部备注 |
| 独立页面 | 目录、联系、成功、隐私、条款的主要正文 | 询盘字段、表单校验规则、邮件模板、法律审核、页面地址 |
| 询盘 | 统一联系/发件/收件邮箱通过全站设置读取 | 发信服务开通、邮箱创建、DNS、Resend 验证、收件箱、CRM |

后台是基于 Git 的网站内容管理工具，没有独立的内容级 RBAC、审批流、定时发布、设备业务数据或询盘 CRM。GitHub 账号需有仓库写权限；仓库层面的权限同时允许更广的代码操作，不能把表单限制当作权限隔离。需要更细角色时应另行规划。
