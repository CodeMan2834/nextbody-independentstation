# NEXBODY 基础访问统计维护

## 当前统计方式

默认记录页面浏览、模块曝光、点击次数和邮件服务确认的成功询盘，不弹出授权框，不创建访客识别 Cookie，不使用指纹，不拼接访客跨页路径。页脚 Disable basic analytics 可退出；浏览器 DNT/GPC 和原来的拒绝设置继续生效。退出设置保存在浏览器本地；旧会话 Cookie 通过删除响应清除。

不采集表单内容、姓名、邮箱或完整来源 URL。事件 UUID 只用于同一事件重试去重，不在浏览器持久保存，也不作为访客或会话标识。接口保护使用两分钟内到期、按分钟更换的 IP 派生限流键，统计库不保存原始 IP。

## 看板操作

1. 打开 /admin/analytics.html，使用有仓库写权限的 GitHub 账号登录。
2. 选择日期、渠道、设备或产品页面，点击应用筛选，立即从数据库查询，响应不缓存。
3. 页面可见且已加载真实数据时，每 5 分钟自动刷新。上报通常在交互后短暂批处理，不是逐秒推送；查询可能不包含尚在传输的事件。
4. 切换来源、内容、模块或询盘概况。询盘概况的各项次数彼此独立，不代表顺序漏斗或转化率。
5. 导出当前汇总 CSV。排名最多100项，不含原始事件。演示数据有醒目标记。

## 指标说明

- 浏览量包括刷新；点击为事件次数，不是独立访客数。重复网络投递按事件 ID 去重。
- 来源按页面上报时的 UTM 或外部域名分类；不跨设备或通过 Cookie 识别人。
- 模块曝光：本次页面的核心标题可见至少一半并持续一秒；不是独立用户曝光。
- 产品筛选仅匹配产品页本身，不包括同一访客随后访问的其他页面。
- 成功询盘由服务器在邮件服务接收确认后单独统计，不关联来源、产品、访客或设备。渠道、设备、产品筛选可能排除该项；这不等于邮件没有发送。
- 管理员、后台、退出、隐私保护信号和已识别机器人不计入。广告拦截或网络失败也可能造成缺失。
- 旧会话模式和新聚合模式分库存表、不混合展示。历史数据保留，不能按新口径反推。

## 数据库与维护

新表 analytics_aggregate_events / analytics_counts 保存独立事件与按日期维度汇总，不含 sid。旧 analytics_sessions / analytics_events / analytics_daily 不再由线上采集写入，按原保留策略到期清理。analytics_limits 用于短期限流。

生产环境：TURSO_DATABASE_URL、TURSO_AUTH_TOKEN、ADMIN_SESSION_SECRET、CRON_SECRET、ANALYTICS_ENABLED。密钥仅放服务端环境变量。

- npm run analytics:migrate：幂等增量建表，不清空旧数据。
- npm run analytics:backup -- <项目外的新文件>：v2快照包含新旧表。
- npm run analytics:restore -- <备份>：只允许新空库，兼容v1旧备份。
- npm run analytics:cleanup：明细90天、汇总365天。

Vercel 每日 UTC02:15（北京时间10:15）调用带鉴权的维护接口。自动异地备份和用量告警仍需独立配置。本实现减少数据处理，不构成针对所有地区的免同意合规认证。
