## 1. 日常维护的五个步骤

1. 打开 `https://nexbodyfit.com/admin/index.html`，确认入口提示为“线上编辑”。点击“进入 GitHub 登录”，再使用负责人授权的 GitHub 账号登录。
2. 从左侧选择栏目，点击其中的内容条目。修改一组相关内容，核对文字、图片和链接。
3. 点击页面顶部“发布”，再点击“立即发布”。等到显示保存完成提示。继续维护前点击“重新载入，继续维护”，从最新内容开始下一次编辑。遇到红色错误提示先修正，不要连续重复发布。
4. 在 Vercel 项目的 Deployments 中确认对应的新部署为 **Ready**，并核对该部署对应的 Git 提交及 Production 环境。保存成功表示内容已提交，不代表网站已经更新。
5. 打开正式网站，检查桌面和手机效果，点击按钮和下载链接。记录修改内容、发布人、时间、Git 提交和 Vercel 部署地址。

底部工具条可“查看网站”“维护手册”“退出 / 结束编辑”。结束工作后退出后台。建议使用电脑维护长表单；平板建议横屏，手机主要用于检查前台效果。

## 3. 修改首页

### 3.1 首屏轮播

- 进入：首页内容 → 首页主要内容 → 首页首屏 → 首屏轮播媒体。
- 建议三条，可配置一条、两条或更多；按实际数量展示。一条时不自动切换，也不显示轮播切换按钮。
- “视频”使用 MP4，并填写视频封面图；“图片”使用 PNG、JPG、WebP、GIF 或 AVIF。
- “内容说明”用于维护识别和无障碍说明，不是额外的首屏广告标题。
- 停留时间单位为毫秒：6500 表示 6.5 秒；允许 3000～60000 的整数。
- 可拖动条目排序；图片默认有缓慢拉近效果。首屏主标题和按钮由同一组文案控制，不随媒体单独改变。
- 视频建议横向 16:9、静音可观看，避免把关键文字放在容易被裁切的边缘。首屏是铺满式背景，手机会改变可见范围；上传后必须检查手机效果。

### 3.2 其他首页板块

“评估流程”可换标题、步骤、视频和封面；“报告视图”可换图片及说明；“F20 宣传影片”可换视频、封面、文案及按钮。“产品系列标题”和“案例区标题”分别控制对应区域的标题和介绍。

FAQ 的每条问题和回答均可编辑。新增或删除条目后检查页面长度及手机折叠效果。首页行业卡片、服务步骤等列表可排序；不要保留空条目。

## 4. 修改产品

产品管理维护 X60、OneScan、F20 三款产品。页面标识和旗舰/配套展示级别由系统保护，不能通过日常运营表单随意更改。新增产品或改产品地址需开发人员同时处理路由、首页入口及测试。

| 字段 | 用途与注意事项 |
| --- | --- |
| 产品名称 / 简称 | 完整名称用于产品信息，简称用于前台醒目标题 |
| 产品卡片图片 | 首页产品系列和产品目录使用；X60 目录图也读取此字段 |
| 产品页主图 | 产品详情页首屏使用；图片需保留完整设备及 Logo，留足安全边距 |
| F20 工作流程图片 | F20 未配置场景视频时使用；其他产品不使用此专用字段 |
| 宣传短句 / 产品简介 | 宣传短句和简介均显示于产品详情；目录及首页也会读取部分文案 |
| 核心卖点 / 功能 / 参数 | 对应产品详情中的能力、规格及相关列表 |
| 报告类型 / 适用行业 / 应用亮点 | 对应“Outputs & applications”区域 |
| 产品场景展示 | 控制场景区小标题、标题、文案、视频、封面。X60、OneScan 需配置视频和封面；F20 可留空视频以展示工作流程图片，配置视频后改为视频展示 |
| 下载资料 | 填资料名称并上传文件或选择本站现有资源；前台会出现 Downloads 区，无资料时不显示 |

注意产品边界：X60 侧重体态、体成分和活动度；OneScan 为步态及足底压力平台；F20 为三维全足扫描。替换图片时核对型号，避免混用设备图。

## 5. 案例新增、排序和删除

1. 进入应用案例 → 案例列表，点击新增案例。
2. 填写不重复的编号，例如 `usecase-rehab-202610`。编号用于系统识别；不要重复。
3. 填“应用场景”“产品”“案例标题”“应用结果”，上传图片并填写准确的图片说明。
4. 拖动案例条目改变展示顺序。第一条使用较大的卡片，其余沿用网站网格排版。
5. 发布后检查首页案例区。删除条目前确认该案例确实不再使用；误删可通过 Git 版本恢复。

目前是应用场景案例卡片，没有独立案例详情页。客户名称、商标、经营效果等信息须使用实际已确认的资料。

## 6. 图片、视频和下载文件

- 通过字段内的文件选择器或顶部“媒体”入口上传。新媒体存放在 `public/images/uploads`，前台路径为 `/images/uploads/文件名`。
- 可以选择已存在的 `/media/...`、`/video/...` 等本站资源路径。图片字段不支持外站图片 URL，以避免域名白名单、跨站失效和前台图片加载问题。
- 建议图片优先 WebP，单张尽量控制在 3 MB 内；需要透明背景时用 PNG。案例图建议 16:10；影片和横幅建议 16:9。
- 视频先压缩为 MP4，建议控制在 20 MB 内。较大长视频先交由技术人员处理，不要把原始拍摄素材直接上传到仓库。
- 下载资料通常为 PDF。请用有辨识度的名称，例如 `f20-brochure-2026-10.pdf`，避免中文空格及 `final-final` 等模糊文件名。
- 替换文件优先上传新的版本名，再更新引用。不要删除仍被产品、首页或其他条目引用的资源。
- 构建会检查配置中的资源路径及站内页面是否存在。资源丢失会使构建失败，Vercel 会继续保留上一次成功的网站版本；此时需修正内容并重新部署。

## 7. 联系邮箱、WhatsApp 与导航

全站联系邮箱目前为 **info@nexbodyfit.com**。这个字段同时用于网站展示、询盘收件人和发件人；旧 `EMAIL_FROM` / `EMAIL_TO` 环境变量不会覆盖它。改变邮箱前，技术人员需确认新邮箱已开通且发信域名在 Resend 已验证。仅修改网页文字不能完成邮件服务开通。

WhatsApp 使用 `+国家码号码`，不加空格，例如 `+971501234567`。留空或保留指定的测试占位号码时，前台隐藏 WhatsApp 按钮。Vercel 中若设置了 `NEXT_PUBLIC_WHATSAPP_NUMBER`，它优先于后台字段；需要让运维控制此项时，由技术人员移除该覆盖并重新部署。

“全站导航”用于页头和页脚；“首页补充导航”只在首页页头额外显示。链接使用本站路径，例如 `/products`、`/contact`、`/#applications`；外站使用完整 `https://...`。不支持 JavaScript 链接。

社交链接仅填写官方账号；留空即不展示。本次移除了原有未经确认的占位社交账号。

## 8. 保存、上线、回滚和多人协作

### 本地编辑

技术人员在主工程运行 `npm run dev`，打开 `http://127.0.0.1:3000/admin/index.html`。本地入口只供同一电脑的维护预览，CMS 代理默认使用 8081 端口并绑定本机地址。点击“进入本地编辑”后，组件可能还显示一次“登录”，点击即可连接本地编辑服务。

本地“发布 / 立即发布”实际是保存文件，不会自动上传 GitHub。刷新本地前台可检查结果；线上更新还需由技术人员提交、推送并确认 Vercel 构建。

### 线上编辑

线上使用有仓库写权限的 GitHub 账号。每次发布会创建内容提交；Vercel 是否触发生产构建，以项目 Git Integration、Production Branch 和部署设置为准。不要把内容保存成功当作收到询盘邮件或网站已发布的证据。

此方案依赖 GitHub 仓库权限，没有独立的“只可改内容、不可改代码”角色；也没有额外的审批流、定时发布或询盘管理列表。需要这些能力时，应由负责人另行配置权限及发布流程。

### 回滚

1. 内容有误但尚未发布：离开编辑器前选择放弃未保存修改，重新打开条目。
2. 已提交的内容有误：请技术负责人在 GitHub Revert 对应内容提交，或恢复相应 JSON 及资源文件后重新部署。
3. 重新部署时先核对提交版本，避免对历史版本点击 Redeploy 而覆盖当前生产内容。
4. 线上紧急异常：技术负责人可在 Vercel 将已确认的成功部署恢复为当前生产版本。仅回退部署后，还需同步修正 GitHub 分支，否则下次发布会再次带入错误内容。

多人不要同时编辑同一个条目。遇到保存冲突，先备份尚未保存的文字，再刷新加载最新版本并重新合并。不要反复覆盖他人的内容。

## 9. 常见问题排查

| 现象 | 检查与处理 |
| --- | --- |
| 提示“线上后台尚未启用” | 技术负责人尚未完成 OAuth 环境变量、回调域名或部署配置；不要启动本机代理来冒充线上后台 |
| Failed to load entry | 本地检查 CMS 代理是否启动且指向主工程；线上检查 GitHub 登录、仓库权限、内容文件及配置是否匹配 |
| 保存失败或提示字段错误 | 按提示修正必填、编号、链接、媒体类型和时间范围，再发布 |
| 保存成功但线上没变 | 查 GitHub 内容提交、Vercel 部署状态及生产域名；确认查看的是 Production，而非旧页面或预览环境 |
| 部署 Failed | 查看日志；先运行 `npm run validate:content` 检查资源、页面地址及内容结构，修正后重新部署 |
| 图片不显示 | 核对是否为本站路径、文件是否存在、大小写和文件扩展名是否正确，再看电脑及手机 |
| WhatsApp 后台改了但前台不变 | 检查 `NEXT_PUBLIC_WHATSAPP_NUMBER` 环境变量是否覆盖；环境变量变更后重新部署 |
| 询盘未收到 | 看表单是否显示成功，再核查 Resend 发送状态、域名验证、接收邮箱及垃圾邮件；网站后台没有收件箱功能 |
| 登录授权失败 | 允许登录弹窗，检查 OAuth 回调 URL、域名和 GitHub 写权限；重新进入授权，不要共享他人的令牌 |
| 媒体删除后构建失败 | 恢复被引用的文件或修正所有引用，重新构建 |

## 附录 A：技术负责人首次开通线上后台

1. 在 GitHub 为此网站创建 OAuth App。Homepage URL 填 `https://nexbodyfit.com`，Authorization callback URL 填 **`https://nexbodyfit.com/api/admin/callback`**。
2. 在 Vercel 对应项目的 Production 环境配置以下变量。Secret 只保存在 Vercel 环境变量中，不写进 Git、前台文件或聊天。

| 变量 | 值 / 作用 |
| --- | --- |
| `CMS_AUTH_MODE` | `github`，明确启用线上后台 |
| `CMS_SITE_URL` | `https://nexbodyfit.com`，授权回调与管理入口的准确域名 |
| `CMS_GITHUB_REPO` | `CodeMan2834/nextbody-independentstation` |
| `CMS_GITHUB_BRANCH` | `main`，需与 Vercel Production Branch 一致 |
| `CMS_GITHUB_CLIENT_ID` | 上述 OAuth App 的 Client ID |
| `CMS_GITHUB_CLIENT_SECRET` | 上述 OAuth App 的 Client Secret |
| `RESEND_API_KEY` | 已验证发信域名对应的邮件服务密钥，独立于 CMS 授权 |

3. 邀请运维账号成为指定仓库协作者，赋予所需写权限，确认分支规则允许采用的内容发布方式。GitHub OAuth 使用 `repo` 授权范围；授权者需理解这是 GitHub 仓库级权限，无法单靠 CMS 表单限制为内容目录。
4. 确认 Vercel 连接上述仓库、Production Branch 为 `main`，Build Command 使用项目的 **`pnpm run build`**（采用 npm 的环境可使用 `npm run build`），并重新部署。环境变量有变更必须重新部署才能生效。
5. 用实际运维账号走完“登录 → 修改一条临时测试文案 → 发布 → Vercel Ready → 正式前台回读 → 恢复原文”流程。记录两次内容提交和两次部署结果。
6. 同时测试无仓库写权限的账号不能使用、退出后不能直接复用页面会话。未通过这一步，不得标记线上后台验收完成。

本次采用的授权实现包含随机 state、HttpOnly / Secure / SameSite cookie、回调域名核对、GitHub 仓库写权限检查和同源弹窗消息。负责人账号已完成真实授权与正式发布；无写权限账号的拒绝路径已通过自动测试，尚未用独立的第二个真实账号重复验证。令牌到期或权限变更后请重新登录，不要关闭令牌过期保护。
